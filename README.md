# Placement Registry TC5

Реестр товарных подборок (плейсментов) в мобильном приложении Торговой Сети X5.

## Статус (актуализировано 2026-08-27)

Единственный источник истины по проекту. Ранее часть материалов дублировалась в
`rpervushin/placement-registry-mvp-tc5` — тот репозиторий архивирован, весь актуальный
контент перенесён сюда.

Сервис реестра реализуется в 3 этапа:

1. **Этап 1 - MVP - сервис учёта плейсментов рекомендаций.** Единый реестр всех рекомендательных плейсментов
   в МП и их настройки - модель ранжирования RecSys, id плейсмента, статус, экран размещения.
   Данные приходят из RecSys (входящая интеграция).
2. **Этап 2 — развёртывание админки.** Встраивание UI реестра с точкой входа в единую
   админку компании (контур LEGO/BDUI) вместо отдельной самостоятельной админки. Может
   идти параллельно с последующей интеграцией через Splitter BFF и с подключением стейкхолдеров для
   поставки кандидатов на встраивание.
3. **Этап 1 - управление правилами встраивания промотируемых медиа-объектов в рекламные плейсменты.**
   Для каждого плейсмента:
   настраивать приоритеты стейкхолдеров (X5 Media, Маркетинг, Контент, Рецепты,
   Трейд-промо), разрешённые типы объектов и их частота, правила разнообразия. Реестр не участвует в обработке запроса
   пользователя - правила при формировании выдачи применяет MS Catalog или Splitter BFF
   (решение целевого сервиса будет принято позже). Оценка разработки - в разработке (см. `TASKS.md`).

Открытый архитектурный вопрос о том, где во время обработки запроса пользователя
происходит встраивания в рекомендации промо объектов: в MS Catalog или в Splitter BFF
(см. `ARCHITECTURE.md` §12).
